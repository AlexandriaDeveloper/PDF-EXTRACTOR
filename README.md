# PDF-EXTRACTOR — Oracle Payroll Extractor

برنامج Windows لاستخراج بنود **صرفية الموظف من Oracle PDF**، والتحقق من الإجماليات وتصدير Excel عربي باتجاه صحيح من اليمين إلى اليسار.

يعتمد على Python وTkinter وpdfplumber وopenpyxl. يدعم *صرفية موظف* كنموذج الإدخال الحالي، ولا يفترض أن «كافر» أو «كشوف صرف» يحتويان تفاصيل بنود بالهيكل نفسه.

> **تنبيه محاسبي:** نجاح القراءة والتصدير لا يعني أن البيانات صحيحة محاسبيًا. يجب مقارنة النتائج مع كشوف Oracle الأصلية قبل الاعتماد عليها.

## التشغيل على Windows

يحتاج Python 3.12:

```powershell
cd F:\Prog-Projects\PDF-EXTRACTOR
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python oracle_payroll_extractor.py
```

1. اختر ملف PDF من نوع «صرفية موظف».
2. اختر **كل الموظفين** أو **موظفًا/مجموعة** باستخدام البحث بالاسم أو الرقم القومي أو رقم الصرف.
3. اختر **إجمالي الاستحقاقات الرسمي** و/أو **إجمالي الاستقطاعات الرسمي** و/أو **الصافي الرسمي**؛ وأضف أي بند أو عدة بنود من القائمة (استحقاقات أو استقطاعات أو معلوماتي).
4. راجع المعاينة ثم صدّر Excel.

ملف XLSX يحتوي على 3 أوراق: **ملخص الموظفين**، **تفاصيل البنود** مع صفحات المصدر وكود الحساب، و**معلومات ومراجعة** تحتوي على التحذيرات وحالة التحقق. يتم حفظ الرقم القومي وكود الجهة ورقم الصرف كنص، والمبالغ كأرقام فعلية داخل Excel. كما تُحمى الخلايا النصية من تفسير المحتوى المُستورد على أنه صيغة Excel.

## مبادئ الدقة المحاسبية

- قراءة هويات الموظفين من الترويسة بشكل مستقل عن البنود المالية. كود الجهة المؤسسي مثل `30200105` ليس كود بند.
- تحديد البند من سياقه: القسم، كود الحساب (8 أرقام)، الوصف، المبلغ ورقم الصفحة؛ لا نخمن نوع البند من موضع الخلية فقط.
- حصص جهة العمل أو الحكومة تُصنف `Informational` وليست استحقاقات نقدية جديدة للموظف.
- البنود المكررة ذات الوصف والكود والنوع المتطابق تجمع داخل عمود التصدير، وتبقى سطورها المصدرية منفصلة في ورقة التفاصيل.
- يستخدم Python `Decimal` للأرقام المالية. الإجماليات والصافي تُقرأ من التقرير الرسمي، ولا يحل محلها جمع آلي غير مؤكد.
- لا تتحول القيمة المفقودة أو غير المثبتة إلى صفر عند وجود تحذيرات. تظهر حالة المراجعة بجانب الموظف.
- الصفحات الممتدة تدمج عند ثبوت الهوية؛ الصفحات بلا ترويسة قبل أول موظف لا تلصق بموظف افتراضي.
- فك الاتجاه العربي يتم باختيار قراءة أفضل اعتمادًا على الكلمات الدالة؛ لا يجري عكس أي نص عربي سليم دون داعٍ.

## الاختبارات وبناء EXE

```powershell
python -m unittest discover -s tests -v
python -m pip install -r requirements-dev.txt
python -m PyInstaller --noconfirm --clean OraclePayrollExtractor.spec
```

ينتج الملف `dist/OraclePayrollExtractor.exe`. ويُنتج GitHub Actions نسخة Windows كـArtifact بعد نجاح اختبارات Windows وLinux. ملفات `build/` و`dist/` و`*.exe` ليست جزءًا من المستودع المصدر بعد الآن.

### التحقق المحلي على بياناتك الأصلية

```powershell
python tools/verify_local.py "F:\path\to\real-payroll.pdf" --expect-employees 219 --expect-net 2864042.24
```

القيم في المثال **ضوابط تخص مجموعة محددة فقط** وليست أرقامًا عامة لأي ملف. استخدم الضوابط المطابقة لكشفك. الأداة لا تطبع بيانات الموظفين، وتتيح `--strict` لرفض أي تحذير.

## البنية

| الملف | دوره |
|---|---|
| `payroll_core.py` | تطبيع العربية، هوية الموظف، البنود والمطابقة المالية |
| `payroll_export.py` | اختيار الموظفين والبنود وإنشاء Excel |
| `oracle_payroll_extractor.py` | واجهة Tkinter والبحث والمعاينة |
| `tests/test_payroll.py` | اختبارات تلقائية ببيانات صناعية |
| `tools/verify_local.py` | فحص خاص لملفات حقيقية على الجهاز |
| `.github/workflows/ci.yml` | اختبارات Windows/Linux وتجهيز EXE |

## حدود معروفة

اختبارات CI على بيانات صناعية، وليست إثباتًا لدقة كل بند في مستندات Oracle الحقيقية. بعض ملفات PDF ذات اتجاه كتابة معقد أو أعمدة نصية متداخلة تحتاج مراجعة يدوية. لا تنشر ملفات صرفية موظف أو بيانات شخصية أو ملفات Excel الناتجة على GitHub أو داخل تقارير أخطاء عامة.
